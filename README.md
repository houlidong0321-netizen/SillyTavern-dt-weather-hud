# 剧情时间天气悬浮窗 + 侧边信息栏（SillyTavern 扩展）

一个 SillyTavern 第三方 UI 扩展。让 AI 每次回复时在正文末尾输出一个结构化数据块，
扩展自动扫描并把信息呈现为一个透明 HUD 悬浮窗 + 可展开的侧边信息栏。

## 功能总览

**悬浮窗（常驻显示）**
- 超大数字时间 `HH:MM`（剧情时间，非系统时间），冒号每秒闪烁
- 日期 + 星期（星期由日期自动推算）
- 天气图标（SVG 线性图标）+ 天气文字 + 温度

**侧边展开栏（点击悬浮窗展开，方向可选左/右）**
- **日历**：月历视图，带待办的日期显示彩色圆点；点击某天查看当日待办；可手动增删待办、点击待办切换完成状态；剧情"当天"高亮标记
- **场景**：当前地点 + 主要人物着装
- **摘要**：最近一章的正文摘要（只显示最后一条，不累积历史章节）

## 运行原理

1. **注入提示词**：通过 `setExtensionPrompt` 注入系统指令，要求模型在每次回复
   正文结束后输出 `<scene_data>` 数据块。注入内容会带上"当前已知剧情状态"作为
   连续性参考，让时间地点合理推进而非随意跳变。
2. **扫描解析**：监听消息渲染 / 编辑 / 删除 / 重滑 / 切换聊天等事件后全量扫描聊天记录：
   - 日期/时间/天气、地点、着装 → 取**最后一条**出现的
   - 章节摘要 → 取**最后一条**
   - 待办 → **累积全部**（自动按内容去重）
3. **渲染显示**：把结果渲染进悬浮窗和侧栏。可选自动隐藏正文中的数据块。

## 数据块格式

```
<scene_data>
[日期: 2026-08-05 | 时间: 09:45 | 天气: 晴 28°C]
[地点: 老城区「灰鸽」咖啡馆二楼靠窗座位]
[着装: 林夏=米色针织开衫，深蓝色长裙; 陈默=深灰色风衣，黑色高领毛衣]
[待办: 2026-08-08 | 红 | 截止：向委员会提交调查申请]
[Chapter_2]2026-08-05 09:20-09:45 灰鸽咖啡馆二楼 陈默出示1998年施工许可影印件……
</scene_data>
```

- **颜色标签**可选：`红 / 橙 / 黄 / 绿 / 青 / 蓝 / 紫 / 粉 / 灰`（也接受英文）
- `[待办: ...]` 可以有多行，也可以完全没有（没有约定事项时模型不输出）
- 各项均兼容全角冒号 `：`，日期分隔符 `- / . 年月日` 都能解析

**章节摘要**采用你指定的硬性法则：简体中文 50-100 字、绝对冷酷的上帝监控视角、
只用"主语+动作+宾语"陈述句、禁止文学修饰与主观评价、明确的情绪转变必须客观记录、
关键转折/权力转移/承诺的原话用双引号保留、只总结本章正文、`[Chapter_X]` 从 1 递增、
格式为「日期+时间（起-止）+地点+摘要」。

## 安装

把整个文件夹放进 SillyTavern 目录：

```
public/scripts/extensions/third-party/dt-weather-hud/
```

重启 SillyTavern 或在扩展面板刷新即可。也可将本文件夹发布为 Git 仓库后，
用「扩展 → 安装扩展」粘贴仓库地址安装。

## 后台设置

点击底部工具栏的 **扩展（魔法棒）** 按钮，展开「剧情时间天气悬浮窗」：

| 设置项 | 说明 |
| --- | --- |
| 启用提示词注入 | 总开关，关闭后仅保留扫描显示功能 |
| 显示悬浮窗 | 隐藏/显示 HUD |
| 自动隐藏正文数据块 | 仅影响显示层，**不修改聊天记录**，扫描照常工作 |
| 注入内容模块 | 分别开关：日期天气 / 地点 / 着装 / 待办 / 摘要，未勾选的不写进提示词 |
| 注入位置 | 聊天中（按深度）/ 提示词最前 / 提示词固定位 |
| 插入深度 | 仅"聊天中"模式生效，0 = 最新消息之后（权重最高） |
| 注入角色 | System / User / Assistant |
| 侧栏展开方向 | 向左 / 向右 |
| 自定义 CSS | 实时覆盖悬浮窗与侧栏样式 |

## 视觉设计

透明 HUD 风格，参考 macOS 小组件 / 极简科技界面：

- 完全透明背景，无卡片、无实色面板、无蓝色调，仅保留文字、细线与微弱发光
- 超大细字重时间居中，冒号独立 `@keyframes` 每秒渐隐渐现
- 左上角、右下角白色 L 型细线角框，加载后延迟渐显（fade-in + glow）
- 整体缓慢呼吸浮动动画（侧栏展开时自动暂停，避免内容晃动）
- 天气图标为纯 SVG 描边图标，**全程不使用任何 emoji**
- 侧栏用极淡底噪保证暗/亮背景下都可读，滚动条细化处理

样式变量集中在 `style.css` 顶部的 `:root`（字号、颜色、发光强度等），
改这里就能整体换风格。也可在后台自定义 CSS 中覆盖任意选择器：

`#dt_weather_hud_panel` · `.dt-hud-time-row` `.dt-hud-hour` `.dt-hud-minute` `.dt-hud-colon`
· `.dt-hud-date-row` `.dt-hud-weather-row` · `.dt-hud-drawer` `.dt-hud-drawer-inner`
· `.dt-hud-tabs` `.dt-hud-tab` · `.dt-hud-cal-grid` `.dt-hud-cal-day`
· `.dt-hud-todo-item` · `.dt-hud-outfit-item` · `.dt-hud-chapter-item`
· `.dt-hud-corner-tl` `.dt-hud-corner-br`

## 预览

直接用浏览器打开 **`demo.html`** 即可查看完整效果（含侧栏、月历、待办、
着装、摘要）。它引用的是扩展真实的 `style.css`，使用示例假数据，
不依赖 SillyTavern，方便你在安装前调整字号、颜色和间距。

## 交互说明

- **点击**悬浮窗时间区域 → 展开/收起侧栏
- **按住拖动**悬浮窗 → 移动位置（位置会被记住；位移小于 4px 视为点击）
- 悬浮窗底部箭头 → 折叠，只留时间行
- 月历左右箭头 → 翻月份；点击日期 → 查看当日待办
- 待办右上 `＋` → 手动添加待办（存在当前聊天的存档里，随聊天走）
- 点击待办条目 → 切换完成状态；手动待办可点 `×` 删除

## 注意事项

- 数据块能否稳定输出取决于模型的指令遵循能力。如果经常漏输出，
  可以把注入位置切到「聊天中」并把深度设为 0，或换更强的模型。
- 如果角色卡/预设里已有类似的状态栏系统，建议关掉本扩展对应的注入模块，
  只保留扫描显示，避免两套指令打架。
- 手动待办保存在**当前聊天的 metadata** 中，换聊天会各自独立；
  剧情解析出的待办则始终跟随该聊天的正文内容实时重算。
- 这个扩展从未在真实 SillyTavern 环境里跑过端到端测试（我这边只做了语法、
  JSON、CSS 配平和类名/ID 交叉校验），首次安装后建议先开一个测试聊天验证。

## 与 Ego 小助手联动

安装了 [Ego 小助手](https://github.com/houlidong0321-netizen/st-offscreen-widgets) 后，本扩展会**直接读取同一个聊天里 Ego 的存档数据**——不发任何请求、不消耗任何 token。

| 显示位置 | 数据来源 |
|---|---|
| 月历条目 | Ego 的**核心待办事项表**（带确切时间，直接落到日历） |
| 月历条目 | Ego 的**日程表**「时节性必然事件」（"8月底：季度总结会"这类会推断成具体日期，条目后带 `?` 表示是推断的） |
| 场景页 · 当前剧情事件 | Ego 的**剧情推演**（含分支，已排除的分支会划掉） |
| 场景页 · 未回收伏笔 | Ego 的**伏笔表** |
| 月历红色条目 | **当前事件导火索的排期**（见下） |
| 右上角 `Ego ↗` | 一键打开 Ego 小助手 |
| 生成中角标 / toast | Ego 广播的生成开始与结束事件 |

未安装 Ego 时相关区块自动隐藏，功能不受影响。可在扩展设置里关闭。

### 日期推断规则

日程表里的模糊说法会以「剧情当前日期」为基准推断：

| 写法 | 推断为 |
|---|---|
| `8月15日` / `2026-08-15` | 精确日期 |
| `8月底` / `月末` | 当月最后一天 |
| `月初` / `X月上旬` | 1 号 / 5 号 |
| `月中` / `X月中旬` | 15 号 |
| `每周三` | 基准日之后最近的周三 |
| 推不出来的 | **不显示**（宁可不标，也不瞎标） |

### 待办去重

合并三个来源（手动 > 正文解析 > Ego 表格）时按**归一化后的文字**去重：剥掉标点、时段词（上午/下午…）、指代今天的说法再比较。所以「今天去机场」和「今天下午去机场」会被识别为同一条，不会重复出现。


### 导火索排期

剧情推演最容易卡在「知道下一个事件是什么，但一直找不到切入点」。

开启「为当前事件的导火索排一个具体日期」后，提示词会把 Ego 当前事件的**导火索**一并发给模型，
要求它排一个具体日期（当前剧情日期之后 1-14 天内），以 `[导火索: YYYY-MM-DD | 说明]` 输出，
扩展解析后作为**红色条目置顶显示在月历**上。

- 已排过期且日期还在未来的，会要求模型沿用同一个日期，不会天天变
- 导火索实际发生后就不再输出
- 事件推进到下一个时，旧的排期自动消失，换成新事件的导火索
- **只为当前这一个事件排期** —— 不给所有事件算日期，省 token，也避免为走不到的分支白算
